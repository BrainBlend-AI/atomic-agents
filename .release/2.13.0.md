# Atomic Agents 2.13.0

## Dependencies

- Replace the exact Instructor pin with `instructor>=1.17.0,<2`. The framework uses the public `instructor.Instructor` and `instructor.AsyncInstructor` exports. (#310)
- Set tested minimums of Pydantic 2.11.4 and MCP 1.8.0. The schema transformer needs Pydantic's support for combining `__config__` and `__base__`; the MCP connector imports a module first shipped in 1.8.0.
- Keep `mcp<2`. Support for MCP 2.x is still pending.

## Runtime fixes

- Accept Instructor's generated response schemas from its reorganized modules. Sync and async calls no longer fail the framework's docstring check on Instructor 1.17.
- Preserve callers' `strict` setting when Instructor forwards it into streaming validation, without passing the keyword twice.
- Exercise real Instructor request preparation and parsing through mocked HTTP transport. Tests cover sync and async calls, streaming, and explicit strict settings in both streaming paths.

## Installation checks

A new CI job runs the suite on the lowest compatible direct runtime dependencies. The clean-wheel import check introduced in 2.12.1 remains in place.

## Compatibility

- Python 3.12 or newer.
- This release requires Instructor 1.17 or newer within the 1.x line. Applications that need Instructor 1.14.5 can stay on Atomic Agents 2.12.1.
- Instructor 1.17 changes integer `max_retries` counting. A value of 3 now permits the first attempt plus three retries, rather than three attempts total. Lower it by one to preserve a previously configured attempt budget. Atomic Agents forwards this setting without changing it.
- No live model-provider calls were used for release verification. The locked and minimum-dependency suites each passed with three credential-gated tests skipped.
